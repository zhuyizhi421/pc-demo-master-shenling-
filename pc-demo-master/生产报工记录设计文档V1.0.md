# 创建生产报工记录 设计文档

## 1. 功能概述

生产报工记录是 MES 系统的核心功能之一，用于记录车间一线人员在完成生产任务后的实际产量上报。报工数据需要经过审核流程确认后，才能参与生产成本核算和数据统计分析。

### 1.1 业务场景

- 车间操作工完成生产任务后，通过 PDA 或 PC 端填报实际产量
- 班组长或车间主任对报工数据进行审核确认
- 审核通过的报工数据用于生产成本计算、绩效统计等

### 1.2 目标用户

| 角色 | 权限 |
|------|------|
| 车间操作工 | 创建报工记录 |
| 班组长 | 创建、查看报工记录 |
| 车间主任 | 创建、审核报工记录 |
| 生产主管 | 查看、审核所有报工记录 |
| 管理员 | 全部权限 |

## 2. 数据模型

### 2.1 生产报工记录表 (production_report)

```typescript
interface IProductionReport {
  // ========== 基础信息 ==========
  id: string                      // 主键ID
  productionTaskId: string        // 生产任务ID
  productionTaskNo: string        // 生产任务编号
  productionExecutionId: string   // 生产执行ID
  productionExecutionNo: string   // 生产执行编号（报工单号）

  // ========== 产品信息 ==========
  productModelId: string           // 产品模型ID
  productModelCode: string         // 产品编号
  productModelName: string         // 产品名称
  productModelSpec?: string        // 产品规格

  // ========== 生产信息 ==========
  productionOrderId: string        // 生产订单ID
  productionOrderNo: string        // 生产订单号
  sourceNo: string                 // 来源单号（如销售订单号）

  // ========== 工序信息 ==========
  processSerial: string            // 工序编号
  techName: string                 // 工艺/工序名称

  // ========== 报工数量 ==========
  reportQty: number                // 报工数量
  qualifiedQty?: number           // 合格数量
  defectiveQty?: number           // 不合格数量

  // ========== 单位与生产信息 ==========
  unitId: string                  // 单位ID
  unitName: string                // 单位名称（件、小时等）

  // ========== 生产区域 ==========
  entityId?: string               // 生产区域ID
  entityName?: string             // 生产区域名称

  // ========== 工作站与人员 ==========
  workStationName?: string        // 工作站名称
  rotationName?: string          // 报工人姓名
  reportName?: string            // 报工人（冗余）

  // ========== 生产批次 ==========
  executionBatch?: number         // 执行批次

  // ========== 来源类型 ==========
  sourceType?: number            // 来源类型（1:PDA 2:PC 3:接口）
  reportType?: number            // 报工类型（1:数量 2:时间）

  // ========== 业务类型 ==========
  bizType?: number               // 业务类型（1:正常报工 2:补报 3:返工）

  // ========== 时间信息 ==========
  reportTime: string             // 报工时间
  createTime: string             // 创建时间

  // ========== 审核信息 ==========
  reviewedQty?: number           // 审核数量
  reviewer?: string               // 审核人
  reviewTime?: string            // 审核时间
  remark?: string                // 备注

  // ========== 其他 ==========
  facilityName?: string          // 工厂名称
  decimalNumber?: number         // 小数位数
  barcode?: string               // 标签码（用于追溯）
}
```

#### 3.2.3 业务逻辑

1. **选择生产订单后**：
   - 自动带出关联的生产任务、产品信息
   - 带出可报的工序列表
   - 根据产品带出默认单位

2. **选择工序后**：
   - 自动带出工艺名称
   - 显示该工序的历史报工记录参考

3. **报工数量逻辑**：
   - 合格数量 + 不合格数量 = 报工数量
   - 修改报工数量时，自动计算合格/不合格数量

4. **权限控制**：
   - 普通用户：只能创建报工，不能审核
   - 审核权限用户：可以创建和审核

## 5. 权限配置

### 5.1 角色权限

| 角色 | 创建报工 | 审核报工 | 查看全部 | 批量审核 |
|------|----------|----------|----------|----------|
| 操作工 | ✓ | ✗ | 本人 | ✗ |
| 班组长 | ✓ | ✗ | 本班组 | ✗ |
| 车间主任 | ✓ | ✓ | 本车间 | ✓ |
| 生产主管 | ✓ | ✓ | 全部 | ✓ |
| 管理员 | ✓ | ✓ | 全部 | ✓ |

### 5.2 数据权限

- 操作工、班组长：只能看到自己或本班组创建的报工记录
- 车间主任：只能看到本车间的报工记录（根据生产区域负责人配置）
- 生产主管、管理员：可以查看所有报工记录

## 7. 技术实现要点

### 7.1 前端实现

1. **生产订单选择**: 使用已有的 SelectFactoryModel 组件
2. **生产区域选择**: 使用 Area 类型的下拉框
3. **表格组件**: 使用现有的 CustomTable 组件
4. **弹窗组件**: 使用 CustomDialog 组件

### 7.2 后端实现

1. **数据验证**: 必填字段校验、数量逻辑校验
2. **生成报工单号**: 格式 REPPORT-YYYYMMDD-XXXXXX
3. **自动填充**: 报工人为当前登录用户，报工时间为当前时间
4. **数据权限**: 根据用户角色过滤可见数据

### 7.3 注意事项

1. 报工数量不能超过剩余可报工数量
2. 同一个工序对同一个生产订单不能重复报工（除非是补报类型）
3. 审核时审核数量不能大于报工数量
4. 审核后需要更新生产订单的完成数量
